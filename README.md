## 项目目标和适用场景

**项目目标**：搭建一套轻量化智能安全老旧小区管理平台，实现报修、租金缴纳、访客申请、安全隐患上报与台账管理，线上跟踪隐患与工单闭环，提升老旧小区安全管理效率。
**适用场景**：基础设施老化的老旧居民小区，用于物业管理员统一处理业主诉求、安全隐患登记、访客准入管理。

## 主要用户角色及各角色的需求

1. **业主**：线上提交报修、登记租金缴纳；查看小区公告、安全提醒；举报电梯挡门、设施损坏等安全隐患；接收管理员工单处理反馈。
2. **访客**：提交临时入园申请，等待管理员审核通行。
3. **管理员**：处理业主报修工单、确认缴费记录；审批访客申请；发布小区公告、安全警告；查看、管理全部安全隐患台账。
4. **安全监测系统（系统内置角色，无前端页面）**：模拟自动上报火情、管道漏水、电梯异常等安全隐患，推送告警给管理员。

## 功能模块划分，以及每个模块包含的具体功能

- 用户权限模块：账号注册登录、角色权限校验
- 报修工单模块：业主提交报修、管理员处理工单、反馈处理结果
- 租金缴费模块：缴费记录登记、缴费成功通知
- 访客管理模块：访客入园申请提交、管理员审核
- 公告通知模块：发布小区公告、安全隐患提醒、不文明行为警告
- 隐患台账模块：业主举报录入、安全监测模拟隐患录入、管理员查看隐患列表


✅ 当前项目范围：
用户角色权限管理；报修工单、租金缴费、访客申请；公告发布；隐患上报与台账管理。

❌ 暂不实现：
不接入真实传感器硬件，安全监测仅后端模拟数据；不对接第三方线上支付，仅保存缴费记录；不细分维修人员岗位，管理员统一处理工单。

## 后续可扩展方向

1. **认证**：引入 JWT 实现登录鉴权，精细化四个角色的访问权限控制
2. **服务拆分**：拆分为用户、报修工单、缴费、访客、公告、隐患台账多个微服务
3. **消息**：使用消息队列实现报修通知、缴费成功提醒、安全隐患告警推送
4. **事务**：工单状态变更、隐患记录新增使用分布式事务保证数据一致性
5. **监控**：增加服务健康检查、隐患告警数量、工单处理时长监控
6. **部署**：基于 Docker 容器，在 WSL/WSL2 环境完成项目部署
